# Hanani — functional and code review

**Date:** 2026-08-08 · **Reviewed:** `master` @ `621c3f2`, version **0.8.0**
(clean working tree)
**Method:** the vertical slice was run end to end on a purpose-built article
(`ingest → atoms → Layer 1 → Layer 2 → persist`), the status/analysis commands
were exercised against the resulting `~/.hanani` store, then the source was read.
Every claim below is backed by a run or a probe, reproduced inline.

---

## Part 1 — Functional review

**Baseline:** `74 passed` in 0.62 s. `ruff check src tests` clean, rule set
pinned (`select = ["E4","E7","E9","F"]`) with the explanatory comment, and CI
gates both.

### What works — and one thing no sibling has

**`hanani gaps` is a first-class honesty mechanism, and it is the best thing in
this repo.** Run against the store this review created:

```
gap analysis: 8 assessed atoms (1 rhetoric-gated) — speed gaps: 8 (rate 100%)
  mechanism coverage: 1/35 (3%)
  rhetoric coverage: 1/31 (3%)
  [speed_gap] 8 of 8 assessed atoms carry an explicit none_evident speed block …
  [signal_without_speed] 2 atoms flagged sensemaking signals at Layer 1 but
    recorded no speed evidence at Layer 2 — assess these first.
  [no_party_linkage] No assessed atom links its speed block to coherence-profile
    party ids — collective LCD constraints cannot bind.
```

A command whose job is to state what the system has *not* established, reporting
3% coverage in plain language and naming what to fix first. Four sibling reviews
found headline numbers that overstated capability; this is the direct opposite,
and it should be the estate's model.

Other things that hold up:

- **The reputation-blind invariant is real.** Grepping for
  `reputation|prestige|credibility|trust_score|weight` across `src/` returns only
  the docstrings asserting the principle and one fallacy label. No outlet
  weighting exists anywhere.
- **Model output is validated against the vocabulary.** `_ask_hits`
  (`pipeline.py:99`) constrains the Hoglah audit to known `FALLACIES` /
  `ENTHYMEME_PATTERNS` keys and drops anything unrecognised — *"an unknown key
  from the model is dropped, never invented."* This is the pattern Deborah's
  allow-list should have used.
- **15 of 18 subcommands carry `help=`** — by a wide margin the best CLI
  documentation in the estate (Tirzah 9/101, Mahalath 3/38).
- **Optional extras degrade with actionable messages:**
  `hanani debate: debate needs the milcah extra (pip install 'hanani[milcah]')`.
- The Keturah manifest advertises six capabilities that all correspond to real
  commands — no under- or over-claiming.
- `hanani docs serve` binds `127.0.0.1`; `__version__` matches `pyproject.toml`.
- Layer-1 records carry their own disclaimer in the data:
  `"notes": ["Layer 1 scaffold — replace with graph traversal + LLM audit"]`.

### Functional defects

#### F1. The Layer-1 rhetoric gate passes textbook fallacies

The stated principle is *"Rhetoric first — Layer 1 before Layer 2; **Weak atoms
do not propagate**."* Ingesting an article containing an appeal to common belief
and an ad hominem:

```
$ hanani ingest article.txt --source-id reuters --title "Odesa depot strike"
  atoms: 7  admissible→Layer2: 7
  robustness: {'Strong': 7}
```

All seven propagate, including *"Everyone knows Moscow will escalate before
winter"* and *"Anyone who doubts this has not been paying attention."* Both were
recorded with `fallacy_hits: []`.

The cause is coverage, not logic:

```
fallacy patterns declared  : 26
enthymeme patterns declared:  5
deterministic cue rules    :  4  covering 4 keys
=> vocabulary with NO deterministic detector: 27 of 31 (87%)
```

Probing the offline floor directly:

```
hits=[]                          <- Everyone knows Moscow will escalate before winter.
hits=[]                          <- Anyone who doubts this has not been paying attention.
hits=[]                          <- Analysts who disagree are simply Kremlin apologists.
hits=['fallacy.false_dilemma']   <- Either we act now or we lose the war entirely.
hits=[]                          <- This is true because the ministry said it is true.
hits=[]                          <- The strike proves the theory, and the theory explains the strike.
```

One of six. Ad hominem, appeal to common belief, appeal to authority and circular
reasoning all pass clean, score `Strong`, and propagate to Layer 2 — which is the
one thing the architecture says must not happen.

`CLAUDE.md` is accurate about this (*"Layer 1/2 matchers (exhaustive) | Scaffold
— pipeline has deterministic cue rules + optional Hoglah"*). The README and the
CLI are not.

#### F2. `ingest` and `rhetoric` report numbers the system itself knows are unsupported

```
$ hanani rhetoric
rhetoric graph version: 0.2
fallacy patterns: 26          ← taxonomy size, presented as capability
```

Four of those 26 are detectable offline. Meanwhile `hanani gaps` — in the same
binary, over the same data — reports `rhetoric coverage: 1/31 (3%)`.

Likewise `hanani ingest` prints `robustness: {'Strong': 7}` with no caveat, while
the gap analyser would immediately flag that the rhetoric layer assessed almost
nothing.

The knowledge exists and is well modelled. The surfaces that a user actually
reads do not consult it.

#### F3. `hanani asssib` declares readiness over a scaffold

```
ASSSIB readiness: True
  mandatory per-atom speed_differential: True
  coherence profiles: True
  collective LCD: True
Hanani is ready to process new sources with ASSSIB-augmented ontology.
```

Every line is true as a statement about *schema*. But `hanani coherence` reports
`0 parties, 0 collectives`, `gaps` reports `[no_party_linkage] … collective LCD
constraints cannot bind`, and `CLAUDE.md` lists coherence/LCD as
*"Scaffold (not auto-wired in ingest yet)"*. "Ready to process new sources" reads
as an operational claim and is a structural one.

#### F4. Optional-extra failures exit 0

```
$ hanani debate
hanani debate: debate needs the milcah extra (pip install 'hanani[milcah]')
$ echo $?
0
```

The message is excellent; the status is not. Same defect as Tirzah F4 — a script
or scheduled run cannot detect that the step did nothing.

#### F5. `CLAUDE.md` reports 68 tests; there are 74

Minor, but `CLAUDE.md` is the agent-handoff document and its "Implemented vs
scaffold vs planned" table is the most accurate status artefact in the repo — it
is worth keeping exact.

## Part 2 — Code review

### High

#### H1 · `pipeline.py` `_CUE_RULES` — four regexes standing in for a 31-key vocabulary

```python
def detect_rhetoric_hits(text: str, *, ask: AskFn | None = None) -> list[str]:
    hits = {key for key, pattern in _CUE_RULES if pattern.search(text or "")}
    if ask is not None:
        hits.update(_ask_hits(ask, text))
    return sorted(hits)
```

Code side of F1. The design is right — deterministic floor plus an optional,
vocabulary-validated model tier — and the model path is genuinely well built. The
floor is simply four rules wide, so with `--hoglah-model` unset (the default, and
the only offline path) 87% of the declared vocabulary is unreachable.

**Fix, cheapest first:** add cue rules for the highest-frequency analytic
fallacies — `appeal_to_common_belief` ("everyone knows", "it is widely accepted"),
`ad_hominem_in_text`, `appeal_to_authority_in_text` ("because X said"),
`circular_reasoning`. Four more regexes roughly triples the floor's reach.
Longer term, make the model tier the default when a model is configured.

#### H2 · `reasoning/__init__.py:114-127` — the gate logic is correct but its inputs and its audit scores are not

```python
valid_hits = [h for h in hits if h in FALLACIES or h.startswith("enthymeme.")]
robustness = "Weak" if valid_hits else "Moderate"
if not valid_hits and not hits:
    robustness = "Strong"
…
audit_scores={c: True for c in AUDIT_CRITERIA},
```

Two separate points.

The **tiering is sound** — `Weak` on a recognised hit, `Moderate` on an
unrecognised one, `Strong` only when clean. Nothing wrong with it; it is starved
by H1.

The **audit scores are a hardcoded pass**. All six criteria
(`chain_completeness`, `evidence_integration`, `qualifiers_falsifiability`,
`analytical_intent`, `update_signals`, `sensemaking_speed_signals`) are set
`True` for every atom, unconditionally. `hanani reasoning` advertises "audit
criteria: 6", and every stored assessment shows all six green — including for the
ad hominem atom. Unlike `robustness`, this field cannot vary at all, so it is
indistinguishable from a real evaluation in the persisted record.

**Fix:** emit `None`/`unassessed` rather than `True` until a criterion is
actually evaluated, so the store records absence of assessment rather than a
passing one. The rest of the repo already models this well —
`speed_differential` uses an explicit `none_evident` for exactly this reason.

### Medium

#### M1 · `store.py:44-45` — malformed records are dropped silently

```python
try:
    record = json.loads(line)
except json.JSONDecodeError:
    continue
```

The docstring calls the store *"tolerant of unreadable lines"*, which is the
right posture for an append-only file — but tolerance should be observable.
Today a truncated or interleaved line vanishes from every summary, gap analysis
and relation computation with no count, no log line, and no field in `hanani
corpus`. For a system whose stated principle is **"Inspectable — JSONL store,
traceable assessment records"**, a silently skipped record is the one thing that
breaks the guarantee.

**Fix:** count skipped lines and surface the count in `corpus`.

#### M2 · `store.py:36` — `_load` reads the whole file into memory, and nothing rotates it

`read_text().splitlines()` on an append-only store with no compaction, rotation
or index. Every `corpus`, `gaps` and `relations` invocation re-reads and re-parses
the entire history. Fine at 9 records; the store is designed to accumulate
indefinitely, and `relations` is O(atoms²) over the same data.

#### M3 · `cli.py` — failures return 0

Code side of F4. The optional-extra guards, and any other non-fatal failure path,
`print(...)` and fall through. Return a non-zero status so the CLI is usable from
a scheduler.

#### M4 · `hanani rhetoric` and `hanani reasoning` report taxonomy size as capability

`fallacy patterns: 26`, `audit criteria: 6`, `mechanism layers: 5`. All are
counts of what is *declared*. Given `gaps` already computes real coverage, these
commands should print both — `26 declared / 4 detectable offline` — which costs
one line and removes the misreading entirely.

### Low

#### L1 · `CLAUDE.md:160` — stale test count (68 vs 74)

#### L2 · `store.py:29-31` — append atomicity has headroom, but not much

Concurrent `hanani ingest` processes append to one file with no lock. On POSIX,
`O_APPEND` writes below `PIPE_BUF` (4096 B) are atomic, and measured records are
comfortably inside it:

```
assessment records: 9   min=716  max=1315  mean=1134
records exceeding 4096B: 0
```

So this is safe today. It stops being safe when Phase 2 adds per-atom
`assessment_summary` narratives, which is on the roadmap. Worth a comment
recording the constraint, or a lock, before that lands rather than after.

## Comparison with the Hoglah, Deborah, Tirzah, Milcah and Mahalath reviews

Hanani inverts the pattern the other five established, and that is the most
useful thing to say about it.

Across the estate the recurring failure was **silence**: a metric that could not
vary, a config typo dropped without a warning, a duplicate definition appended
without comment, an error message replaced by a class name. In every case the
system knew less than it appeared to and said nothing about the gap.

Hanani has the opposite architecture. `gaps` exists solely to state what has not
been established; `speed_differential` uses an explicit `none_evident` rather
than an absent field; the model tier validates against a fixed vocabulary and
drops what it does not recognise; the Layer-1 record carries its own "this is a
scaffold" note into the store. This is the most epistemically careful codebase of
the six.

Its defect is the mirror image: **the honest mechanism is not wired to the
surfaces**. `gaps` knows rhetoric coverage is 3%; `rhetoric` prints 26; `ingest`
prints `Strong: 7`; `asssib` prints "ready". Nothing lies — each number is a true
statement about a different thing — but a reader assembling them gets a picture
the system's own analyser would contradict.

One shared defect does carry over exactly: `hanani debate` failing with exit 0 is
the same as `tirzah ask` failing with exit 0 (Tirzah F4). Worth fixing as a
convention across both.

## Suggested order

1. **H2 audit scores** — stop writing `True` for six unevaluated criteria. This
   is a one-line change that removes a fabricated signal from the persisted
   record, and the repo already has the right idiom (`none_evident`) to copy.
2. **H1** — four more cue rules (common belief, ad hominem, appeal to authority,
   circular reasoning). Roughly triples the offline floor and closes the
   "Weak atoms do not propagate" gap for the most common cases.
3. **F2/M4** — have `rhetoric` and `ingest` print the coverage that `gaps`
   already computes. Cheapest possible fix for the largest misreading.
4. **F3** — reword `asssib` readiness to distinguish schema-ready from
   operationally-wired, matching what `CLAUDE.md` already says.
5. **F4/M3** — non-zero exit codes.
6. **M1, M2, L1, L2** — small.

Nothing here is architectural, and unusually for this estate the *design* needs
no revision at all: the layering, the reputation-blind rule, the vocabulary
validation and the gap analyser are all right. What is missing is coverage in one
matcher and a habit of routing the gap analyser's answers into the commands
people actually run.
